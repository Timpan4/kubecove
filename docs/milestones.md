# Planning and milestones

KubeCove uses GitHub Issues for concrete work and GitHub Milestones for goal-level grouping. Active status, ownership, acceptance criteria, and release targeting should be recorded there rather than duplicated in a Markdown checklist.

Existing unchecked items have not been declared migrated. Before relying on one, consult the [v0.10.3 milestone checklist](https://github.com/Timpan4/kubecove/blob/app-v0.10.3/docs/milestones.md), confirm that a corresponding GitHub Issue exists, and create or triage it through the normal maintainer workflow when authorized.

Use these sources for current facts:

- [GitHub Issues](https://github.com/Timpan4/kubecove/issues) for actionable work and bugs;
- [GitHub Milestones](https://github.com/Timpan4/kubecove/milestones) for grouped delivery goals;
- [CHANGELOG](../CHANGELOG.md) and [GitHub Releases](https://github.com/Timpan4/kubecove/releases) for shipped behavior;
- [Product and architecture](product-and-architecture.md) for current principles and boundaries;
- [ADRs](decisions/) for accepted architectural decisions.

Do not infer delivery commitments from product-direction examples. Security-sensitive additions require an ADR before implementation.
