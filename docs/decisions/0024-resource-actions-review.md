# ADR 0024: Selected-resource actions and change review

## Status

Accepted for the requested variant D implementation.

## Decision

The Actions tab uses inline rows, an action filter, visible permission locks, and pending edits collected into one server dry-run and review. Deployment supports replicas, pause/resume, restart, rollback to an owned ReplicaSet revision, container edits, metadata edits, and exact deletion. StatefulSet supports replicas, restart, container and metadata edits, and deletion. DaemonSet supports restart, container and metadata edits, and deletion. Pod and ConfigMap retain exact deletion and gain metadata edits. Dynamic resources and Secret edits remain outside this operation allowlist. The existing selected-resource YAML editor remains the path for other supported manifest edits.

Container edits address regular containers by name and support image, literal environment variable changes, and resource requests/limits. Unchanged environment references and unrelated fields must survive. Metadata edits affect the selected object's labels and annotations, not its Pod template or immutable selector.

Rust owns narrowly typed reads, permission checks, dry-run patches, revision ownership validation, and apply/delete. No arbitrary patch or YAML payload is added to the Actions command. Preview returns current and API-server-produced YAML for a proper diff. It also stores the canonical request, resolved kubeconfig source, reviewed patch, normalized patch dry-run result, target identity, and rollback source identity in a backend-owned review. Execution accepts only that review's opaque identifier. It atomically consumes the review before cluster access, then checks the resolved source and reviewed identities before repeating the exact reviewed patch as a server dry-run. The normalized result must match the reviewed result before the patch is applied. Delete repeats its dry run and uses the reviewed target identity as its preconditions. Its response is not compared because Kubernetes generates `deletionTimestamp` during each dry run. Rollback restores the complete owned revision Pod template, rather than only its image.

Each backend session holds one in-memory pending resource-action review. Starting a new preview supersedes the previous review in that session, including a preview still in flight. A review is single-use and is not restored after validation, transport, dry-run, or apply failure. The user must preview again after any execution attempt. Server sessions therefore isolate browser tabs and signed-in identities. The native client owns the same store for its process lifetime. Reviews are neither persisted nor shared across a restart.

Global Settings > Advanced exposes `skipChangeReview`, default false, with an explicit warning before enabling it. It skips the successful review popup only. Server dry-run remains mandatory. Exact deletion always opens the review, which names the target's kind, name, context, namespace and controlling owner, and says what follows the delete. Every supported deletion is confirmed by the explicit `Delete <Kind>` button. Typing the resource name is never required, regardless of ownership, replacement eligibility, lifecycle or workload revision. The controlling owner is display metadata read from the selected object's `ownerReferences`; it does not require owner or replacement-demand lookups. Consequence text must qualify possible recreation rather than promise a replacement. Failed checks open the review error state. These rules apply to the Actions tab; selected-resource YAML apply retains ADR 0006's explicit second Apply action.

Permission denial leaves an action visible and locked with its required Kubernetes verb and resource. Failed or indeterminate permission checks do not claim access. The API server remains authoritative, including at execution. Successful actions refresh details, YAML, revisions, and resource lists. Changing target or kubeconfig source invalidates drafts and previews. Independent actions preserve pending drafts; returning from their execution refreshes the baseline before those drafts can be reviewed again.

## Implementation contract

The new command family is `get_resource_action_state`, `preview_resource_action`, and `execute_resource_action`. TypeScript wrappers are `getResourceActionState`, `previewResourceAction`, and `executeResourceAction`. `get_resource_action_state` takes a read-only `ResourceActionStateRequest` extending `ClusterOperationTarget` with optional `kubeconfigEnvVar`; it does not require an action, edits, or confirmation. Preview takes `ResourceActionRequest`. Execution takes `ResourceActionConfirmation` and backend-owned `ResourceActionReviewStore` state.

The state command takes `ResourceActionStateRequest`, which extends `ClusterOperationTarget` with optional `kubeconfigEnvVar: string`. Reading state requires no action, edits, or confirmation. Container edit fields other than `name` are optional deltas in TypeScript and default to empty collections when absent in Rust.

`ResourceActionRequest` extends `ClusterOperationTarget` with `action: "edit" | "restart" | "pause" | "resume" | "rollback" | "delete"`, optional `edits: ResourceActionEdits`, optional `revision: number`, and optional `kubeconfigEnvVar: string`. The edit request is a single atomic patch for that object. It carries no confirmation or reviewed identity fields.

`ResourceActionConfirmation` has only `reviewId: string` and rejects unknown fields. `execute_resource_action` accepts no target, action, edits, revision, kubeconfig selector, patch, or identity from the caller. Unknown, superseded, cross-session, and already-used identifiers fail without cluster access.

`ResourceActionEdits` has optional `replicas: number`, `containers: ResourceContainerEdit[]`, `labels: Record<string, string | null>`, and `annotations: Record<string, string | null>`. `ResourceContainerEdit` has `name: string`, optional `image: string`, `env: ResourceEnvEdit[]`, `requests: Record<string, string | null>`, and `limits: Record<string, string | null>`. `ResourceEnvEdit` has `name: string`, optional `value: string`, and optional `remove: boolean`. These maps represent deltas; null removes only the named key. Environment edits preserve untouched references and remove valueFrom only for an explicitly replaced variable.

`ResourceActionState` has `target: ClusterOperationTarget`, `uid: string`, `resourceVersion: string`, optional `replicas: number`, optional `paused: boolean`, `containers: ResourceActionContainer[]`, `labels: Record<string,string>`, `annotations: Record<string,string>`, `permissions: ResourceActionPermission[]`, and `revisions: ResourceActionRevision[]`.

`ResourceActionContainer` has `name: string`, `image: string`, `env: {name:string; value?:string; referenced:boolean}[]`, `requests: Record<string,string>`, and `limits: Record<string,string>`. `ResourceActionPermission` has `action: ResourceActionRequest["action"]`, `allowed: boolean`, `reason: string`, and `requiredPermission: string`. `ResourceActionRevision` has `revision: number` and `images: string[]`. Revision lookup failures must be visible without hiding unrelated actions.

`ResourceActionPreview` has `reviewId: string`, `target: ClusterOperationTarget`, `effect: string`, `beforeYaml: string`, `afterYaml: string`, `uid: string`, `resourceVersion: string`, and optional `revisionUid: string`, `revisionResourceVersion: string` and `controller: ResourceActionController`. `ResourceActionController` has `kind: string`, `name: string`, read from the owner reference marked `controller: true`. Only delete previews return `controller`. For rollback, the preview returns the identity of the same owned ReplicaSet object used to build its dry-run patch. Execution re-resolves that selected owned revision and rejects a missing or changed UID/resourceVersion before using the stored patch. This prevents a revision template changed after review from being applied under an unchanged Deployment identity. The server stores the selected revision number, narrow source identity values, and reviewed patch; the caller receives no patch or template. Execution returns existing `ClusterOperationResult`. State and preview follow existing resource-display redaction and server-owned metadata cleanup. Secret objects are never returned by this family.

## Verification

Record failure modes before implementation: denied/unknown permissions, invalid or retargeted inputs, stale target/version, source changes, unowned or changed revisions, lost environment references or metadata, failed dry-run, a repeated patch dry-run result that differs from the reviewed one, execution without preview, changed execution payloads, replay, concurrent double execution, cross-session use, consumption after failure, delete with review skipped, request completion after changing target, and pending drafts lost by independent actions. Verify those boundaries through focused backend tests and the Actions browser E2E flow. Run required frontend/backend checks and review the final diff before publication.
