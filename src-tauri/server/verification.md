# Server verification contract

The dated sections below record evidence from 2026-10-09 to 2026-10-11, before the first server release. They are kept as history and describe the server as it was then. Since then:

- Clients run in independent concurrent sessions. The single-owner model, ownership takeover and **Take over session** described below no longer apply (see [ADR 0023](../../docs/decisions/0023-multi-user-sessions-and-persistence.md)).
- Releases publish server archives and container images.
- The desktop remote client signs in to OIDC servers as well as token servers ([ADR 0031](../../docs/decisions/0031-gpui-remote-sign-in.md)).
- Test counts have grown past the numbers quoted.

## What the tests must reject

The security boundary can fail by accepting a missing or wrong startup token, a duplicate or wrong Host, a missing or cross-origin browser POST or WebSocket, a non-loopback plaintext listener, a native dialog command, an oversized body, or a stale owner's resume token. Tests must reject these inputs before any backend command runs. Valid same-origin cookie requests and native bearer requests must still work.

The session lifecycle can fail by allowing an old request to mutate a new owner's state, retaining streams or exec after takeover, expiring a reconnected owner, stopping forwards during the approved grace window, or leaving listeners alive after expiry. Lifecycle tests use explicit notifications and Tokio's controlled clock, not fixed sleeps.

Channel delivery can fail if a continuously replenished lower channel ID starves another channel, if removed channels accept late messages, or if reconnect retention silently loses output. Queue tests cover fair delivery, revocation and explicit gap frames.

Tunnel registration can report a listening forward for a missing context or an unresolved Service. Registration must resolve through the shared Pod/Service path and return the actual resolved Pod name and port. Every subsequent TCP connection resolves again. The HTTP/WS smoke rejects a missing context at registration and checks resolved target metadata before sending bytes.

Dispatch can fail by omitting a desktop command, decoding snake_case instead of the frontend's camelCase arguments, accepting malformed typed payloads, or serializing an application error into a different shape. A parity test compares the complete desktop command list with server commands and the desktop-only list.

The native remote client can fail by dropping the `/api/v1` route prefix, losing a configured reverse-proxy path, or returning an HTTP error body as a successful result. The URL regression test covers both root and prefixed origins. Native E2E requires an unknown command to reject with the server's serialized `AppError`.

Browser verification must use real server responses. It covers authentication, kubeconfig source settings, workspace import/export, channel delivery, and ownership takeover. A token link must strip its fragment and authenticate even when bundling moves the runtime into a shared chunk. Kubernetes-backed live sessions additionally require the existing isolated E2E cluster and artifact reports.

## Delivery and verification limits

The 2026-10-11 PR preparation checks pass: frontend typecheck, lint, docs checks, Rust formatting, desktop `cargo check`, 108 focused browser, typed-wrapper and release tests, the release dry run, and the complete pre-commit hook. The Nix Rust vendor build reproduced a stale `cargoHash` after the dependency changes. Updating it to the measured vendor hash made `nix build .#kubecove.cargoDeps` pass in the official Nix container against the locked flake. This proves dependency vendoring, not a complete Nix application build.

Independent Opus, Sol and Luna reviews covered the complete unpublished diff. Corrections reject native bearer credentials over non-loopback plaintext HTTP before any request, enforce Access expiry for in-flight commands even without a revocation token, remove unused native remote credential persistence, restore desktop development update settings, and align the operator documentation. The URL and expiry regressions failed before their corrections and pass after them.

The initial tunnel drain correction exposed a missing upload EOF signal. An owner-scoped `tunnel_eof` message now releases the upload sender while draining response frames. The actual HTTP/WebSocket smoke failed against the preceding server binary on EOF, then passed with the rebuilt server. `KUBECOVE_NATIVE_REMOTE_PROBE=1 bun e2e/headless-smoke.ts` additionally ran the production Rust desktop client against the same isolated Kubernetes WebSocket fixture. It delivered 278528 echoed bytes, completed upload shutdown, observed stream closure and removed native tunnel senders and listeners. It also verified pod-side EOF and error termination while the laptop write half remained open. All 50 automated server tests and server all-target Clippy pass; two manual browser fixtures remain ignored. Kubernetes v4 port-forward closes the whole stream on upload EOF, so this does not prove response-after-FIN support in a real pod.

The native UI E2E assertion now waits for connection closure after echo delivery. Its rerun is blocked because neither `Xvfb` nor `xvfb-run` is accessible in this environment. The previously recorded seven native WebKitGTK tests passed before these review corrections; the new console transport check does not prove the final UI revision. All five T3 browser tabs were closed at the user's request.

Native disconnect now clears active state, channels, tunnels and the socket task before returning. The remote HTTP close runs as a best-effort task bounded by the server's configured session grace, and store write guards are released before teardown. Reconnect handshakes and retry sleeps use the same absolute grace deadline. Focused tests verify local close returns while the test server withholds its response and that a terminal tunnel error releases its download sender while reaching a pending handshake waiter. The close regression failed against the old implementation before correction. The final focused client tests, desktop all-target/all-feature Clippy, formatting and diff checks pass.

Release packaging is implemented and documented, but no release has published server archives or a container image. Focused release and CI workflow checks, docs checks and the release dry run pass. The independent server, lifecycle, command parity and credential-store review reported no findings. Those checks do not prove hosted cross-platform release builds.

Desktop remote integration is implemented. Its independent review found that an ordinary typed command error cleared active frontend channels. The client now checks connection status before clearing those mappings. Host changes reset all cached queries, and a disconnected selected host never falls back to local Kubernetes access. The parent owns the integrated worktree.

Native E2E ran on an isolated temporary Xvfb display and keyring session. The existing host display `:99` is unreachable from this execution environment and was left running. Preserve the `desktop` gates in `commands/mod.rs` so desktop dependencies stay out of the server build.

The full isolated Kubernetes E2E suite has not been rerun for this deployment. Earlier direct Docker API access was denied; the operator build used existing sudo access. The live k0s HTTP/WebSocket checks above do not substitute for that suite. Hosted cross-platform release builds are also unverified. No product release was published or milestone marked delivered. The live Authentik deployment is operator-managed; its recorded Origin CA certificate renewal remains the operator's responsibility. Desktop remote connections still require token authentication, and all permitted users share one active server owner and the configured Kubernetes identity.
